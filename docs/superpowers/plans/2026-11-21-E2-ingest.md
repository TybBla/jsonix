# E2 — Ingest produkcyjny: plan etapu

> Dla agentów: realizuj TYLKO swoje zadanie, w TDD (najpierw test, potwierdź, że pada; potem kod). Pracujesz w osobnym git worktree na gałęzi `etap/E2/<id>`, utworzonej z `etap/E2-ingest`. Commituj w konwencji `typ(zakres): opis` z linią `Co-Authored-By`. Nie pushuj. Nie zmieniaj plików spoza listy „Pliki”. Przed commitem: `python -m ruff check .`, `python -m ruff format --check .`, `python -m pytest -q` muszą przejść (sprawdzaj kod wyjścia, nie przepuszczaj wyniku przez `tail`). Raport: pliki, ostatnia linia pytest, hash commitu.

**Cel:** wierny, czysty tekst z każdego PDF-a, z mapowaniem na strony (do trace i podświetlania w GUI), z bezpiecznym OCR dla skanów i przewidywalnym zachowaniem przy uszkodzonych plikach.
**Roadmapa:** E2 w `docs/superpowers/plans/2026-11-21-roadmap-produkcyjna.md`. **Gałąź etapu:** `etap/E2-ingest`.

## Ograniczenia globalne
- Tylko biblioteki open source z licencją zgodną z przeniesieniem praw na UZP: MIT/BSD/Apache 2.0. **Wykluczone: PyMuPDF (AGPL).** Narzędzia GPL (pdftotext/poppler) wolno użyć wyłącznie jako punktu odniesienia w benchmarku, nie jako zależności.
- Wszystko instalowalne przez `pip` na Windows i Linux, bez binarek systemowych (laptop testowy nie ma Tesseracta ani GPU).
- OCR jest opcjonalny: brak pakietu OCR nie może wywrócić aplikacji, a dokument dostaje wtedy ostrzeżenie.
- Zbiór testowy UZP nie zawiera skanów bez warstwy tekstowej, więc OCR to zabezpieczenie i nie może pogorszyć dokumentów z tekstem.
- Kontrakty: rozszerzamy `Document` wyłącznie polami z wartościami domyślnymi; istniejące wywołania muszą działać bez zmian.
- Bramka `python -m eval.gate --split all` nie może pokazać regresji. Zmiana tekstu może zmienić klasyfikację: poprawa wymaga `--update-baseline` zatwierdzonego przez orkiestratora, a pogorszenie blokuje.

## Decyzje projektowe orkiestratora (wiążące)
1. **Rozszerzenie kontraktu** (`odw2json/contracts.py`):
   ```python
   @dataclass
   class Document:
       path: Path
       text: str                      # tekst po czyszczeniu, strony złączone "\n\f\n"
       pages: list[str]               # tekst stron po czyszczeniu
       ocr_used: bool = False
       page_offsets: list[int] = field(default_factory=list)  # offset początku strony i w `text`
       backend: str = ""              # np. "pypdfium2", "pypdf", "ocr:rapidocr"
       warnings: list[str] = field(default_factory=list)
       def page_of(self, offset: int) -> int | None: ...       # numer strony (0-based) dla offsetu w `text`
   class IngestError(Exception):     # uszkodzony / zaszyfrowany / nie-PDF; komunikat czytelny dla człowieka
   ```
2. **Backendy wymienne przez konfigurację:** `config/app.yaml` → `ingest: {backend: <nazwa>, fallback_backends: [...], clean: [lista kroków], ocr: {enabled: true, engine: rapidocr, min_chars_per_page: 30}}`. Rejestr backendów w kodzie, a wybór i kolejność kroków w YAML (zgodnie z zasadą „konfiguracja bez zmian kodu”).
3. **Czyszczenie jako lista czystych funkcji** `str -> str`, uruchamianych w kolejności z konfiguracji. Funkcje nie mogą zmieniać cyfr ani polskich liter.

## Na co zwrócić uwagę przy review
1. Polskie znaki: ą, ć, ę, ł, ń, ó, ś, ź, ż mają przetrwać każdy backend i krok czyszczenia (pdftotext w E0 gubił „ę” i „ł”, a pypdf nie).
2. Numery (NIP z myślnikami lub spacjami, IBAN w grupach po 4 cyfry) nie mogą zostać sklejone ani rozcięte przez czyszczenie dzielenia wyrazów.
3. `page_offsets` po czyszczeniu muszą wskazywać właściwe strony (test: znany tekst ze strony 2 → `page_of` = 1).
4. Zaszyfrowany PDF bez hasła, plik 0 B, plik HTML z rozszerzeniem `.pdf` i PDF z 0 stron dają `IngestError`, a pipeline loguje błąd i jedzie dalej.
5. OCR nie może uruchamiać się dla stron, które mają tekst. Czas przetwarzania zbioru treningowego nie może istotnie wzrosnąć.

### T1 — Miara pokrycia tekstu (Sonnet, medium) · fala 1
**Pliki:** `eval/ingest_coverage.py`, `tests/test_ingest_coverage.py`, `eval/README.md` (sekcja).
- `coverage_for_doc(text: str, gt: dict, doc_type: str) -> Coverage(found, total, missing: list[(path, value)])`: dla pól „dosłownych” sprawdza, czy wartość GT występuje w tekście po normalizacji porównawczej (casefold, zwinięte białe znaki, ujednolicone cudzysłowy i myślniki; dla pól cyfrowych porównanie samych cyfr ciągiem w tekście bez separatorów).
  - Pola dosłowne: wszystkie `nazwa`, `tytul`, `imie_nazwisko`, `mail`, `numer_postepowania`, `numer_transakcji`, `miejscowosc`. Pola cyfrowe: `krs`, `nip`, `regon`, `pesel`, `na_rachunek`, `z_rachunku`.
  - Pomijane: daty, kwoty, BZP, TED, `czynnosc_*`, `typ`, `przez-pelnomocnika`, `prowadzacy_postepowanie` (występują w tekście w innej formie).
  - Imiona: jeśli brak dokładnego trafienia, zalicz trafienie tokenów rdzeniowych (pierwsze 4 litery każdego słowa) jako `found_fuzzy` i raportuj osobno, bo w tekście bywają w innym przypadku.
- CLI `python -m eval.ingest_coverage [--backend NAME] [--split dev|holdout|all] [--json PATH]`: przechodzi przez sprawy, wczytuje PDF wskazanym backendem (`odw2json.ingest.load(path, backend=...)`; do czasu T3 obsłuż brak parametru: użyj `load(path)`), raport: pokrycie globalne, per typ, per pole, lista braków.
- Testy: syntetyczny tekst + GT (dokładne trafienie, NIP z myślnikami, IBAN ze spacjami, imię w dopełniaczu → fuzzy, wartość nieobecna → missing); test na `przyklad_01` z obecnym `ingest.load`, gdzie pokrycie > 0.9.
- **Done:** testy zielone; w raporcie liczby dla obecnego pypdf (baseline pokrycia).

### T2 — Czyszczenie tekstu (Sonnet, medium) · fala 1
**Pliki:** `odw2json/ingest/clean.py`, `tests/test_clean.py`.
- Funkcje `str -> str`, każda z rejestru `CLEAN_STEPS: dict[str, Callable]`:
  - `unicode_nfc`
  - `nbsp_to_space`, które zamienia na spację również ` ` i ` `
  - `ligatures` (ﬁ, ﬂ, ﬀ, ﬃ, ﬄ)
  - `quotes` (zamienia „ ” « » ‚ ’ na proste cudzysłowy, ale **zachowuje** oryginał w osobnej funkcji, jeśli test GT wymaga; najpierw zmierz to T1)
  - `dashes` (– — ‒ ‐ na `-`)
  - `dehyphenate`: łączy `wyra-\nzu` tylko między literami, nigdy gdy po obu stronach są cyfry
  - `join_wrapped_lines`: łączy łamane wiersze akapitu, zostawia puste linie i linie nagłówkowe w stylu `Zamawiający:`
  - `collapse_spaces`
  - `strip_page_artifacts`: usuwa `Strona X z Y` i powtarzające się stopki
- `clean_text(text: str, steps: list[str]) -> str`; nieznany krok → `ValueError` z listą dostępnych.
- Testy jednostkowe na każdy krok, w tym: NIP `123-456-78-90` i IBAN `60 1010 1010 …` nietknięte przez `dehyphenate`; polskie litery nietknięte; idempotencja (`f(f(x)) == f(x)`) dla każdego kroku.
- **Done:** testy zielone; żadnej integracji z `ingest` (to robi T3).

### T3 — Ingest wymienny, offsety stron, błędy (Sonnet, high) · fala 1 → integracja T2 w fali 2
**Pliki:** `odw2json/contracts.py` (tylko rozszerzenie wg decyzji 1), `odw2json/ingest/__init__.py`, `odw2json/ingest/backends.py`, `config/app.yaml` (sekcja `ingest`), `odw2json/pipeline.py` (obsługa `IngestError`: wpis do `report.errors` z czytelnym komunikatem), `requirements.txt`, `tests/test_ingest.py`.
- Backendy: `pypdf` (obecny), `pdfplumber`, `pypdfium2`; interfejs `extract_pages(path) -> list[str]`; rejestr `BACKENDS`.
- `load(path: Path, backend: str | None = None, cfg: dict | None = None) -> Document`: wybór z argumentu lub z `config/app.yaml`; fallback na kolejny backend, gdy pierwszy rzuci wyjątek albo zwróci pusty tekst przy niepustym PDF (ostrzeżenie w `warnings`); czyszczenie stron krokami z konfiguracji (w fali 1 lista pusta, a T2 podepnie się w fali 2); składanie `text` z separatorem `"\n\f\n"` i liczenie `page_offsets`; `page_of`.
- Rozpoznanie błędów → `IngestError` (np. „Plik zaszyfrowany – brak hasła”, „Plik nie jest PDF-em”, „PDF bez stron”).
- Testy: każdy backend czyta `przyklad_01` (polskie znaki obecne); `page_of` dla tekstu ze strony 2; wybór backendu z konfiguracji i z argumentu; fallback przy wyjątku pierwszego backendu (monkeypatch); `IngestError` dla pliku 0 B i dla nie-PDF; pipeline zapisuje `IngestError` do `report.errors` i przetwarza resztę.
- **Done:** testy zielone, domyślny backend bez zmian (`pypdf`) do decyzji z T4, bramka bez regresji.

### T4 — Benchmark backendów i decyzja (Sonnet, medium) · fala 2 (po T1, T3)
**Pliki:** `scripts/bench_ingest.py`, `docs/decyzje/E2-backend-pdf.md`, `config/app.yaml` (tylko wartość `ingest.backend` i `clean`, po decyzji orkiestratora).
- Dla każdego backendu × (bez czyszczenia, z czyszczeniem T2): pokrycie T1 (globalne, per pole, dokładne i fuzzy), czas na dokument, liczba braków polskich znaków (wykrywanych heurystycznie przez porównanie z GT), błędy, klasyfikacja (wynik bramki). pdftotext (jeśli dostępny w systemie) tylko jako odniesienie.
- Raport z tabelą i **rekomendacją** (backend + lista kroków czyszczenia); decyzję zatwierdza orkiestrator, a agent wpisuje ją do `config/app.yaml`.
- **Done:** raport w repo, konfiguracja ustawiona, bramka: pokrycie ≥ baseline pypdf i brak regresji `eval.gate` (ewentualna poprawa klasyfikacji → aktualizacja baseline zatwierdzona przez orkiestratora).

### T5 — OCR fallback (Sonnet, high) · fala 2 (po T3)
**Pliki:** `odw2json/ingest/ocr.py`, `requirements-ocr.txt`, `odw2json/ingest/__init__.py` (tylko wywołanie OCR dla stron poniżej progu), `tests/test_ocr.py`, `docs/decyzje/E2-ocr.md`.
- Najpierw research (≤ 30 min): RapidOCR (rapidocr / rapidocr-onnxruntime, Apache 2.0) — czy ma model łaciński z polskimi znakami, rozmiar modeli, czas na stronę A4 na CPU; renderowanie strony do obrazu przez pypdfium2. Alternatywy tylko pip, bez Tesseracta. Wynik w `docs/decyzje/E2-ocr.md`.
- `ocr_page(path, page_index) -> str`; w `load`: strona z tekstem < `min_chars_per_page` → OCR → `ocr_used=True`, `backend="...+ocr:rapidocr"`; brak pakietu → ostrzeżenie „OCR niedostępny” bez wyjątku.
- Testy: OCR nie uruchamia się dla `przyklad_01` (monkeypatch licznika); przy braku pakietu ostrzeżenie zamiast wyjątku; jeśli pakiet jest zainstalowany (`pytest.importorskip`, test oznaczony `slow`), to skany z `data/train/negatywne/` (3 pliki bez tekstu) dają tekst > 200 znaków z polskimi literami.
- **Done:** testy zielone; czas `eval.gate --split all` nie rośnie o więcej niż 10%; skany negatywne nadal klasyfikowane jako nieznane (bramka).

### T6 — Odporność: fixture'y uszkodzonych plików (Haiku, low) · fala 2 (po T3)
**Pliki:** `tests/fixtures/broken/` (generowane), `scripts/make_broken_fixtures.py`, `tests/test_ingest_robustness.py`.
- Skrypt generuje (pypdf): pusty plik 0 B, plik HTML z rozszerzeniem `.pdf`, ucięty PDF (pierwsze 50% bajtów `przyklad_01/odwolanie.pdf`), PDF zaszyfrowany hasłem `test`, PDF z jedną pustą stroną, nazwę z polskimi znakami i spacjami.
- Testy: każdy przypadek → albo `IngestError` z niepustym komunikatem, albo `Document` z ostrzeżeniem (pusta strona); pipeline na katalogu z tymi plikami + 1 poprawnym → poprawny przetworzony, reszta w `report.errors`, kod wyjścia CLI 0.
- **Done:** testy zielone, fixture'y w repo (< 1 MB łącznie).

## Follow-upy z realizacji (do kolejnych etapów)
- pdfplumber kończy strony bez `\n`, więc `strip_page_artifacts` nie usuwa stopki przed `\f` (`Strona 1 z 11\fOdwołanie …`). Niski priorytet, bo pdfplumber jest drugim zapasowym backendem (raport T4).
- OCR (rapidocr) jest dobry do klasyfikacji, ale nie do wiarygodnej ekstrakcji pól (pieczęcie, pojedyncze literówki). Jeśli w E3+ skan okaże się pozytywem, ekstrakcja ze skanu wymaga osobnej oceny.
- Instalacja OCR: `pip install -r requirements-ocr.txt` (~107 MB, modele w paczce, bez pobierania przy uruchomieniu); CI go nie instaluje.
- Dla E4: regexy pól muszą dopuszczać `\s+` (także nową linię) między etykietą a wartością (np. `REGON\n999642785`).
- Czyszczony tekst ma cudzysłowy ASCII `"` (krok `quotes`); wzorce nie mogą zakładać typograficznych cudzysłowów.
- Offsety odnoszą się do tekstu po czyszczeniu; podświetlanie bbox w PDF wymagałoby nowego opcjonalnego pola w `Document`/trace.
- Poprawki po review E2: walidacja sekcji `ocr`, cache OCR (względny `cache_dir` od ROOT_DIR, zapis atomowy, wersja cache + wersja rapidocr), `\f` w tekście backendu, domyślny backend `pypdfium2` i scalanie częściowej konfiguracji z `config/app.yaml`.
